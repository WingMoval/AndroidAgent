## 1. 整改前基线 (callback_baseline_before.txt)

### UI 路径 (ChatActivity)

**UI Send (BEFORE):**
```

  → text = input.text.toString().trim(); if blank return
  → runtime ?: "No provider configured"; if busy "A run is already in progress"
  → autoFollow = true

  → renderTranscript()
  → input.setText("")
  → setBusy(true)
```

## 4. Send 共享入口 (callback_debug_send_shared_entry.txt)

### AFTER 路径

**UI Send:**
```
ChatActivity.onSend()
  → text = input.text.toString().trim(); if empty return
  → input.setText("")                    # 纯 UI
  → autoFollow = true                    # 纯 UI
  → lifecycleScope.launch {
      result = HostActions.send(text)    # 共享入口
      when (result) {
          Rejected -> updateRunStatus(msg); renderStatus()
          Sent -> logTrace(); if Interrupted -> updateRunStatus("Stopped.")
      }
      renderTranscript()
    }
```

**Debug Send:**
```
DebugBridge.handleSend(text, writer)
  → if blank -> error("blank send rejected")
  → if runtime == null -> error("runtime not ready")
  → if runtime.isBusy -> busy()
  → accepted()
  → result = HostActions.send(text)     # 共享入口
  → Log.i("debug run finished: $result")
```

**HostActions.send (唯一公共语义):**
```
1. text.isBlank() -> Rejected("blank send rejected")
2. runtime == null -> Rejected("runtime not ready")
3. r.isBusy -> Rejected("busy")
4. transcriptModel.onUser(text)     # User block (1 次)
5. setBusy(true)
6. setRunStatus("Running...")
7. notifyUiUpdate()
8. outcome = r.send(text)           # AgentRuntime.send (1 次)
   finally { setBusy(false) }
9. if Interrupted -> setRunStatus("Stopped.")
10. notifyUiUpdate()
11. return SendResult.Sent(outcome)
```

### 结论
- **SEND_SHARED_ENTRY = YES**
- User block: exactly 1
- Run count: exactly 1
- busy: true→false 各 1 次

## 6. DebugBridge 启动独立性 (debugbridge_startup_independence.txt)

### 整改

`ensureDebugBridge()` 从 "provider Applied 之后" 移到 "onCreate 最前面"。

```
BEFORE:
  onCreate -> tryDeviceLocalConfig -> switchNode -> switchProvider
    -> Applied -> applyConfigCanonical -> ensureDebugBridge()
    -> Rejected -> (no ensureDebugBridge)  ← bridge 永远不启动

AFTER:
  onCreate -> ensureDebugBridge()          # 始终启动 (debug build)
         -> tryDeviceLocalConfig -> switchNode -> switchProvider
           -> Applied / Rejected (bridge 已启动, 命令诚实返回 not ready)
```

## 7. Provider 启动诊断 (provider_startup_diagnosis.txt)

### 根因 (历史: bridge 未启动)
整改前: `ensureDebugBridge()` 只在 `applyConfig` 内调用, `applyConfig` 只在 `switchNode` Applied 分支执行。Provider load 失败 (Rejected) 时 bridge 永远不启动。

### 修复
`ensureDebugBridge()` 移到 `onCreate` 最前面, bridge 动态读 SessionHolder。

### 网络限制
设备在移动数据网络 (10.5.64.95), 非 Wi-Fi。`adb reverse tcp:18080 tcp:18080` 已设置但设备无法到达 PC fixture。这是设备/网络环境限制, 非产品 bug。

```
PROVIDER_STARTUP_ROOT_CAUSE = ensureDebugBridge 曾在 provider Applied 之后才调用 (已修)
PROVIDER_STARTUP_FIX = ensureDebugBridge 移到 onCreate 最前面, bridge 动态读 SessionHolder
```
