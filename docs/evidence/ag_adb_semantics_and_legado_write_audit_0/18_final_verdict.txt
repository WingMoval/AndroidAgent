Q2 — Why does `adb shell "cat <path>"` differ from `adb shell cat <path>`?
ADB_SHELL_CAT_QUOTED = FAIL            (Gate C2, exit 127)
ADB_SHELL_QUOTE_DIFFERENCE_ROOT_CAUSE =
  Outer local /system/bin/sh collapses the double-quoted "cat /path" into ONE
  logical argv element. AtCliMain (AdbCliArgs.serializeToRemoteCommand,
  AT.CLI-0.1) re-serializes each logical argv element with POSIX single-quotes,
  so that one element becomes one single-quoted token '"cat /path"'. The
  remote adbd shell parses it as a single word and tries to exec an executable
  literally named "cat /path" -> exit 127 (command not found).
  Root cause = D3 REMOTE_SHELL_QUOTING (via D2 argv model). NOT permission,
  NOT missing binary.
ADB_SHELL_ARGUMENT_MODEL =
  argv list: outer sh tokenizes -> adb() fn "$@" -> AtCliMain per-element
  single-quote -> joinToString(" ") -> remote adbd sh re-parses.
CAT_FAILURE_WAS_ANDROID_PERMISSION = NO

FINDING_1 (the `adb shell "..."` quoted-form failures) =
  TOOL GUIDANCE GAP   (secondary: LLM MISUSE)
  - The embedded adb CLI's two-pass shell-parsing (outer sh -> single-quote
    re-serialization -> remote sh) makes double-quoted multi-word commands
    collapse to one remote word. This is NOT an AT defect (the behavior is

  - AT_RUNTIME_DEFECT = NO. LIKELY_ROOT_CAUSE = the model did not understand
