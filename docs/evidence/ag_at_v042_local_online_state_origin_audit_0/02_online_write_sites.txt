=== SITES THAT CAN INCORRECTLY MARK "ONLINE" ===

NONE FOUND.

The online_ flag is ONLY set to true at line 90 of plain_tcp_connection.cpp,
which is ONLY reached after RX_CNXN is received in handleAuth().

The isOnline() predicate is a bare bool read:
  bool PlainTcpAdbConnection::isOnline() const { return online_; }

It does NOT check:
  - socket validity
  - hub running
  - RX_CNXN receipt (already consumed)
  - data flow

But it is ONLY set to true after RX_CNXN, so it is CORRECT at the moment of setting.
The question is whether it is INCORRECTLY CLEARED or whether the transport dies
without clearing it.

=== EAGAIN DOES NOT CLEAR online_ ===

rxLoop() line 93-100:
  if (idleTimeout) { LOGI("RX_IDLE_TIMEOUT: continuing"); continue; }

EAGAIN/ETIMEDOUT is treated as "transport still alive" and the loop continues.
online_ is NEVER cleared on EAGAIN.

This means:
  1. Handshake completes -> online_ = true
  2. adbd stops sending data (session "offline")
  3. HUB08 gets EAGAIN -> continues (online_ stays true)
  4. isOnline() returns true forever
  5. connectLocalhost() would say "ALREADY ONLINE" (if called again)
  6. executeShellLocalhost() would try to use the dead transport

But in our trace, the command path goes through AdbRuntime.executeShell()
(Wireless), NOT executeShellLocalhost() (Local). This is the divergence.
