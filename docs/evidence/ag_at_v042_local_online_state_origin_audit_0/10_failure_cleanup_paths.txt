=== RUNTIME TRANSPORT LOSS (NOT A CONNECT FAILURE) ===

When the transport dies AFTER successful connect (e.g., adbd closes session):

  rxLoop() readPacket() fails
  -> if EAGAIN: continue (online_ NOT cleared, g_local NOT reset)
  -> if real failure: markTransportLost() + failAll + break
     -> online_ = false, but g_local still non-null
     -> HUB exits, but g_local not reset until next connectLocalhost

This is NOT a "stale state leak" in the traditional sense:
  - online_ is correctly set to false on real failure
  - g_local is torn down by the next connectLocalhost (teardown at line 401-406)

The EAGAIN case is the PROBLEM:
  - online_ stays true (EAGAIN treated as "alive")
  - g_local stays non-null
  - HUB keeps running (EAGAIN loop)
  - But adbd is no longer sending data (session "offline")
  - isOnline() returns true (incorrectly, from a functional standpoint)
