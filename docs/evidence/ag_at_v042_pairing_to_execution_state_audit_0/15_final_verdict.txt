=== INFERENCE ===

1. The execution route divergence (LAYER 4→5) is caused by either:
   a. Cross-thread stale read of activeTransport (WIRELESS instead of LOCAL)
   b. localhostConnected() returning false at command time

2. If (a): the fix is to make activeTransport @Volatile or use AtomicReference.

3. If (b): the fix is to investigate why isOnline() returns false at command
   time despite the HUB being in an EAGAIN loop (transport "alive").

4. Both (a) and (b) point to the SAME underlying issue: the LOCAL transport
   state is not reliably visible/usable at command execution time.

=== MINIMUM_FIX_DIRECTION ===

1. Make AdbRuntime.activeTransport @Volatile (or AtomicReference).
   This ensures the CLI bridge worker thread sees the latest value.

2. Add a diagnostic log in AdbBackend.ensureConnected() recording:
   - activeTransport value
   - localhostConnected() result
   - connectionState().isOnline result
   This would definitively distinguish (a) from (b).

3. If localhostConnected() returns false despite isOnline() being true in
   the HUB thread, investigate the native transport state visibility.
