PROOF (source + device):

SOURCE:
  AndroidShellToolImpl constructor:
    Executor { command -> adapter.executeLocal(command) }
  
  AtExecutionAdapter.executeLocal():
    val sourceLine = ensureCliBootstrapCurrent()?.trimEnd('\n', ' ')
    val sourcePrefix = sourceLine?.let { "$it && " } ?: ""
    val wrapped = "cd ${shellQuote(appFilesDir.absolutePathPath)} && ${sourcePrefix}$command"
    localEngine.execute(ATExecutionRequest(wrapped, timeoutMs))

  Key: localEngine is a SEPARATE ATEngine instance (Local backend).
  It does NOT call ensureReady(). It does NOT check ADB pairing.
  The `adb` shell function bootstrap is sourced (so `adb` is available),
  but if the user's command is `id` or `pwd`, the adb function is never called.
  Even if `adb` IS called and fails (unpaired), the local shell still works —
  it just gets exitCode=1 from the adb function.
