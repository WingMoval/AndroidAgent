## What is AndroidAgent?

AndroidAgent (AG) is an autonomous AI agent that runs on an Android phone.
An OpenAI-compatible provider drives an adaptive tool loop: the model
autonomously calls tools, observes results, and reasons until a final answer.

**AG = Intelligence, AT = Execution.** AG owns the agent loop, sessions,
providers, and tool contracts. Android execution (ADB connection, pairing,
shell) is provided by the separate AndroidTerminal (AT) project; AG consumes
AT v0.4.4 (GAV 4.0.0) prebuilt artifacts as vendored AARs for a
self-contained build.

## Why v0.2.0?

This is the first public release of the project. Internal 0.1.x development
(pre-publication) is not listed as a public release; the version line starts
at 0.2.0 for the public audience.

## V1 → V2 Evolution

V1 and V2 are one continuous Git history, not two projects:

- **V1**: early AndroidAgent, agent tightly coupled to Android execution / ADB.
- **V2**: continuous evolution on the same history, forming the formal
  AG = Intelligence / AT = Execution separation with the AT consumer
  boundary (vendored AARs).

## Highlights

### Agent Core

- Adaptive tool loop with per-Run step limit (`DEFAULT_MAX_STEPS = 8`).
- Provider-agnostic `ModelProvider` contract; OpenAI-compatible provider
  with streaming + tool calls (e.g. OpenRouter).
- Structured `RunOutcome` semantics, including `Interrupted`.

### Tools

- `android_shell`: shell execution over ADB via the vendored AT Engine
  (one-shot semantics).
- `network`: HTTPS GET fetch, public network only, full SSRF guard.
- `file`: read-only access to `filesDir/agent/` (read / search / list / stat).

### ADB

- Built-in ADB management surface: status, Reconnect, Pair / Re-pair, open
  Wireless Debugging settings.
- Per-app private, self-generated ADB identity.
- AT-owned pairing via the composition facade.

### Session

- Durable TopicSession persistence (Room/SQLite); cold-restart restore.
- Session list, switch, rename, delete (cascade).
- Stop / Interrupt with a structured terminal outcome; partial transcript
  preserved.

### Run Control

- Direct Stop (no confirmation); double-stop and no-active-run are
  structured no-ops.
- Cancellation propagates Core → Provider/Tool → Transport; exactly one
  terminal `RunFinished(Interrupted)`.

## Architecture

```text
AndroidAgent = AG Engine + Tool Layer + Host
  :ag-core / :ag-runtime      pure JVM, no Android/AT/Room dependencies
  :tool-android-shell         AT Engine consumer (via :integration-at)
  :tool-network               platform HttpsURLConnection, no AT
  :tool-file                  APP_SELF read-only
  :app (AGA)                  Composition Root + UI
```

## Known Limitations

1. **G-b1**: a local one-shot child process dispatched to AT may survive
   Stop; external side effects are not rolled back.
2. **Generic mutation approval** is not yet complete (register-and-allow
   policy).
3. **No general browser / search / JS / POST** capability; network is
   HTTPS GET fetch only; file tool is read-only.
4. **Per-Run 8-step limit** (`DEFAULT_MAX_STEPS = 8`).
5. **0.x active development**: APIs may change incompatibly; no Rewind /
   Redo / Fork / Checkpoint; no MCP / multi-agent / persistence (RAG).

## Installation

1. Install `AndroidAgent-v0.2.0-release.apk` on an arm64 Android device
   (Android 8.0+ / minSdk 26).
2. Configure an OpenAI-compatible provider (auto-load of
   `filesDir/provider.local.json`, or the manual UI).
3. For `android_shell`, complete ADB pairing for the target device in the
   ADB management surface.
